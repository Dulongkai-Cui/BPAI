# 数据库模型、迁移与业务映射

> 信息来源范围：`frontend/src/lib/db/schema.ts`、`frontend/src/lib/db/client.ts`、`frontend/drizzle/*.sql`。更新时间：2026-04-11。
>
> 目标：当你需要新增字段、判断表关系、追某个业务模块依赖哪些表、确认迁移顺序时，优先查本页。

## 1. 数据层总体形态

当前正式数据层为：

- ORM：`drizzle-orm`
- Driver：`pg`
- 连接入口：`frontend/src/lib/db/client.ts`
- Schema 定义：`frontend/src/lib/db/schema.ts`
- Migration：`frontend/drizzle/*.sql`

`frontend/src/lib/db/client.ts` 当前默认连接：

```text
postgresql://bpai:bpai@localhost:5433/bpai_dev
```

来自：
- `process.env.DATABASE_URL`
- 无 env 时回退到默认本地连接

## 4. 关键表说明

### 4.1 认证与工作区基础

#### `users`
- 主键：`id`
- 关键字段：`email`、`roleKey`、`roleLabel`、`teamLabel`、`passwordHash`、`primaryWorkspaceId`
- 作用：用户主表
- 关键索引：`users_email_unique`

#### `sessions`
- 主键：`id`
- 外键：`userId -> users.id`
- 作用：登录 session
- 典型调用：`auth/server.ts`

#### `workspaces`
- 主键：`id`
- 关键字段：`name`、`kind`、`ownerUserId`、`visibility`
- 作用：个人工作区/协作工作区统一底座

#### `workspace_members`
- 外键：`workspaceId -> workspaces.id`、`userId -> users.id`
- 唯一键：`workspaceId + userId`
- 作用：工作区成员关系

#### `collaboration_spaces`
- 外键：`workspaceId -> workspaces.id`、`ownerUserId -> users.id`
- 关键字段：`tone`、`documentCount`、`systemFormCount`、`dissolvedAt`
- 作用：合作空间业务层对象
- 说明：与 `workspace` 强绑定，属于“协作工作区”的业务封装

## 5. 内容资产域

### 5.1 `content_assets`
- 主键：`id`
- 外键：`ownerUserId -> users.id`、`workspaceId -> workspaces.id`
- 关键字段：
  - `kind`
  - `title`
  - `originalFileName`
  - `mimeType`
  - `sizeBytes`
  - `storageKey`
  - `currentVersion`
  - `trashedAt`
- 作用：文件资产主表

### 5.2 `folder_nodes`
- 作用：文件夹树
- 关键字段：`workspaceId`、`contentKind`、`scope`、`parentFolderId`、`systemKey`、`name`
- 说明：文档、表格、演示共享一套 folder tree 结构

### 5.3 `file_placements`
- 外键：`assetId -> content_assets.id`
- 关键字段：`rootFolderId`、`innerFolderId`、`isTrashed`、`isDeleted`
- 作用：资产在工作区中的放置关系
- 注意：一个资产通过 `file_placements_asset_unique` 限定为单 placement

### 5.4 `user_workspace_view_states`
- 唯一键：`userId + workspaceId + contentKind`
- 作用：用户个人浏览器状态

### 5.5 `workspace_shared_states`
- 唯一键：`workspaceId + contentKind`
- 作用：合作空间共享浏览状态

## 6. AI 会话与执行域

### 6.1 `conversation_threads`
- 外键：`userId -> users.id`、`workspaceId -> workspaces.id`
- 字段：`title`、`status`、`lastMessageAt`、`metadata`
- 作用：BP Ask 会话线程

### 6.2 `conversation_messages`
- 外键：`threadId -> conversation_threads.id`
- 唯一键：`threadId + sequence`
- 字段：`role`、`content`、`tokenEstimate`、`metadata`
- 作用：线程消息流

### 6.3 `conversation_summaries`
- 外键：`threadId -> conversation_threads.id`
- 字段：`kind`、`summaryText`、`messageCount`、`fromSequence`、`toSequence`
- 作用：长对话压缩与摘要
- 当前已见用法：rolling summary

### 6.4 `memory_facts`
- 关键字段：`scopeKind`、`scopeId`、`factType`、`factKey`、`factValue`、`confidence`
- 唯一键：`scopeKind + scopeId + factKey`
- 作用：BP Ask 事实性记忆层
- 说明：支持按 user/thread/workspace/document/work_order 等多层 scope 存储

### 6.5 `execution_tasks`
- 外键：`userId`、`threadId`、`workspaceId`、`sourceMessageId`
- 关键字段：
  - `status`
  - `executorKind`
  - `primaryIntent`
  - `targetDomain`
  - `executionMode`
  - `goal`
  - `needsMemory/needsTools/requiresWrite/requiresConfirmation`
  - `targetRefs`、`constraints`
- 作用：把一次用户请求抽象为调度任务

### 6.6 `execution_results`
- 外键：`taskId -> execution_tasks.id`
- 唯一键：`taskId`
- 字段：`summaryText`、`responseText`、`structuredPayload`
- 作用：保存执行产出

## 7. 工单主域

### 7.1 `work_orders`
- 主表，工单域锚点
- 关键字段：
  - `workOrderNo`
  - `title`
  - `businessType`
  - `sourceType`
  - `projectName/siteName/siteAddress`
  - `stage/status/priority/warningStatus`
  - `currentResponsibleTeam/currentResponsibleUserId`
  - `collaborationSpaceId`
  - `nextAction`
  - `materialCompleteness`
  - `missingItemCount`
  - `blockingItemCount`
  - `latestProgressSummary`
  - `archivedAt`
- 外键：
  - `currentResponsibleUserId -> users.id`
  - `createdByUserId -> users.id`
  - `collaborationSpaceId -> collaboration_spaces.id`
- 唯一键：`workOrderNo`

### 7.2 `source_intakes`
- 外键：`workOrderId -> work_orders.id`
- 作用：工单来源/受理信息
- 关键字段：`sourceChannel`、`initiatorName`、`sourceAccount`、`requirementSummary`、`confirmationStatus`

### 7.3 `dispatch_executions`
- 外键：`workOrderId -> work_orders.id`
- 当前 schema 已接入 `assignedSquadId -> engineering_squads.id`
- 关键字段：`assignedTeamLabel`、`assignedUserId`、`plannedStartAt/EndAt`、`executionStatus`、`warningStatus`
- 作用：工单派单和执行轮次

### 7.4 `delivery_resources`
- 外键：`workOrderId -> work_orders.id`
- 作用：回单、图纸、资源、设计包交付状态
- 关键字段：`returnSheetStatus`、`drawingDeliveryStatus`、`resourceEntryStatus`、`designPackageStatus`

### 7.5 `missing_items`
- 外键：`workOrderId -> work_orders.id`
- 作用：缺项/阻塞材料管理
- 关键字段：`stage`、`itemType`、`isBlocking`、`ownerUserId`、`status`

### 7.6 `work_order_document_links`
- 外键：`workOrderId -> work_orders.id`
- 关键字段：`linkType`、`targetType`、`targetId`、`linkedWorkspaceId`
- 作用：把工单与文档资产/文件夹/外部引用挂接

## 8. 工程队域

### 8.1 `engineering_members`
- 作用：施工成员主数据
- 关键字段通常包括成员身份、状态、可调度性
- 上游服务：`engineering-team/server.ts`

### 8.2 `engineering_squads`
- 作用：施工编队
- 上游调用：创建编队、派单分配
- 与工单的关系：`dispatch_executions.assigned_squad_id`

### 8.3 `engineering_squad_members`
- 作用：编队与成员的多对多关系
- 角色枚举：`leader | member | reserve`

## 9. 关键关系图（简化）

```text
users
├─ sessions
├─ workspaces (owner)
├─ workspace_members
├─ content_assets (owner)
├─ work_orders (creator / responsible)
├─ source_intakes / dispatch_executions / missing_items / delivery_resources (部分提交或负责人)
└─ conversation_threads / execution_tasks / memory_facts

workspaces
├─ workspace_members
├─ content_assets
├─ folder_nodes
├─ user_workspace_view_states
├─ workspace_shared_states
├─ collaboration_spaces
└─ conversation_threads / execution_tasks (可选 workspace scope)

work_orders
├─ source_intakes
├─ dispatch_executions
├─ delivery_resources
├─ missing_items
└─ work_order_document_links

content_assets
└─ file_placements

conversation_threads
├─ conversation_messages
├─ conversation_summaries
├─ memory_facts
└─ execution_tasks
     └─ execution_results
```

## 10. migration 与业务能力映射

### `0000_nosy_mister_fear.sql`
- 作用：基础账号、工作区、文档与协作底座
- 重点对象：
  - `users`
  - `workspaces`
  - `workspace_members`
  - `sessions`
  - `content_assets`
  - `folder_nodes`
  - `file_placements`
  - 浏览器状态相关表
  - `collaboration_spaces`
- 业务意义：让登录、个人空间、合作空间、文件资产、浏览器状态先成立

### `0001_striped_master_mold.sql`
- 作用：工单主域首批落地
- 重点对象：
  - `work_orders`
  - `source_intakes`
  - `dispatch_executions`
  - `delivery_resources`
  - `missing_items`
  - `work_order_document_links`
- 业务意义：形成“来源受理 -> 派单 -> 施工 -> 回单/图纸/资源/设计 -> 缺项跟踪”闭环

### `0002_gorgeous_sally_floyd.sql`
- 作用：工程队域落地
- 重点对象：
  - `engineering_members`
  - `engineering_squads`
  - `engineering_squad_members`
  - 并把派单接入 squad 维度
- 业务意义：工单与工程队开始真正联动

### `0003_jittery_old_lace.sql`
- 已核验内容：新增 BP Ask 会话与记忆层的首批数据库对象
- 新增对象：
  - `conversation_threads`
  - `conversation_messages`
  - `conversation_summaries`
  - `memory_facts`
- 新增枚举：
  - `conversation_thread_status`
  - `conversation_message_role`
  - `conversation_summary_kind`
  - `memory_scope_kind`
- 业务意义：
  - 把 BP Ask 从前端壳层/临时状态推进到可持久化的线程、消息、摘要、记忆事实模型
  - 为长对话压缩、跨轮记忆、按 scope（user/thread/workspace/document/work_order）存事实打底
- 典型上游：`frontend/src/lib/bp-ask/server.ts`
- 典型下游能力：
  - 线程列表
  - 消息顺序存储
  - rolling summary
  - memory fact upsert

### `0004_mean_vapor.sql`
- 已核验内容：新增执行任务与执行结果层
- 新增对象：
  - `execution_tasks`
  - `execution_results`
- 新增枚举：
  - `execution_task_status`
  - `execution_executor_kind`
  - `execution_result_status`
- 关键字段能力：
  - `primary_intent`
  - `target_domain`
  - `execution_mode`
  - `goal`
  - `needs_memory`
  - `needs_tools`
  - `requires_write`
  - `requires_confirmation`
  - `target_refs`
  - `constraints`
- 业务意义：
  - 让 BP Ask 的调度判断不只是文字输出，而是能结构化记录“这次想做什么、应该由谁执行、是否需要记忆/工具/写入/确认”
  - 为后续接真正执行器（如 `kimi`、`longxia`、`system`）铺路
- 典型上游：`frontend/src/lib/bp-ask/dispatch.ts`、`frontend/src/lib/bp-ask/server.ts`
- 典型下游能力：
  - dispatch preview
  - 执行记录追踪
  - 结果摘要/结构化响应保存

## 11. 新增字段/表时的操作建议

### 新增字段
1. 改 `frontend/src/lib/db/schema.ts`
2. 生成或手写对应 migration
3. 检查所有相关 route / service / 页面展示
4. 若是枚举值，检查前端 label 映射是否同步

### 新增表
1. 先确定属于哪个业务域
2. 确认是否已有相近表能承载
3. 明确与 `users/workspaces/work_orders/conversation_threads` 中哪个做锚点
4. 添加 migration 后，再补 server service 和 route

### 修改工单或 AI 表前
- 工单域：同步检查工单详情页、列表页、派单、阶段资料上传
- AI 域：同步检查 BP Ask shell、消息接口、rolling summary、memory fact upsert 逻辑
