## 1. 这套说明书解决什么问题

BPAI 当前已经同时包含 Next.js 前端、App Router API、Drizzle/Postgres 数据层、OnlyOffice/CAD 文档链路、工单与工程队业务域，以及 BP Ask AI 调度/记忆雏形。每次开发如果重新遍历仓库，会消耗大量上下文。

本目录的目标是作为后续人类/AI 开发前的“快速定位层”：

- 想改页面：先查页面入口、组件、调用 API。
- 想改接口：先查 Route Handler、服务层、依赖表。
- 想改数据库：先查 schema、migration、业务映射。
- 想接 AI：先查 BP Ask 的前端入口、消息链路、记忆/任务表。
- 想查运行依赖：先查环境变量、脚本、外部服务、存储位置。

## 4. 按开发任务快速定位

### 4.1 新增或修改一个页面

1. 查页面入口：`frontend/src/app/**/page.tsx`
2. 查相关组件：`frontend/src/components/<domain>/**`
3. 查页面是否服务端取数：搜索页面中的 `requireCurrentUser`、`get*Data`、`list*`。
4. 查是否调用 API：客户端组件中搜索 `fetch("/api/`。
5. 跳到 [01_前端页面_组件_数据链路.md](./01_前端页面_组件_数据链路.md)。

典型链路：

```text
frontend/src/app/work-orders/[workOrderId]/page.tsx
-> frontend/src/components/work-order/*
-> frontend/src/app/api/work-orders/[workOrderId]/**/route.ts
-> frontend/src/lib/work-order/server.ts
-> frontend/src/lib/db/schema.ts
```

### 4.2 新增或修改一个 API

1. 查 route：`frontend/src/app/api/**/route.ts`
2. 查鉴权：`getCurrentUser` 或 `requireCurrentUser`，来自 `frontend/src/lib/auth/server.ts`
3. 查服务层：通常在 `frontend/src/lib/<domain>/server.ts`
4. 查表：`frontend/src/lib/db/schema.ts`
5. 跳到 [02_API路由_后端职责_调用链.md](./02_API路由_后端职责_调用链.md)。

### 4.3 新增数据库字段或表

1. 查 schema：`frontend/src/lib/db/schema.ts`
2. 查已有 migration：`frontend/drizzle/*.sql`
3. 查 DB client：`frontend/src/lib/db/client.ts`
4. 查相关服务层是否使用表对象。
5. 跳到 [03_数据库模型_迁移_业务映射.md](./03_数据库模型_迁移_业务映射.md)。

### 4.4 接入或扩展 BP Ask AI 能力

1. 前端入口：`frontend/src/app/bp-ask/page.tsx`
2. 客户端 shell：`frontend/src/components/bp-ask/bp-ask-shell.tsx`
3. API：`frontend/src/app/api/bp-ask/**/route.ts`
4. 服务层：`frontend/src/lib/bp-ask/server.ts`
5. 调度：`frontend/src/lib/bp-ask/dispatch.ts`、`frontend/src/lib/bp-ask/intents.ts`
6. 数据表：`conversation_threads`、`conversation_messages`、`conversation_summaries`、`memory_facts`、`execution_tasks`、`execution_results`
7. 如只改 BP问问当前链路，跳到 [04_AI链路_BPAsk_记忆_调度.md](./04_AI链路_BPAsk_记忆_调度.md)。
8. 如讨论 Agent、MCP、CLI、Skill、Longxia 总架构，跳到 [11_AI Agent架构_MCP_CLI_Skill_Longxia总设计.md](./11_AI%20Agent架构_MCP_CLI_Skill_Longxia总设计.md)。

### 4.5 排查运行依赖或外部集成

1. 查脚本和依赖：`frontend/package.json`
2. 查 env：`frontend/.env.local.example`
3. 查 DB：`frontend/src/lib/db/client.ts`
4. 查 OnlyOffice 回调：`frontend/src/app/api/onlyoffice/callback/route.ts`
5. 查内容存储：`frontend/src/lib/content/server.ts`
6. 跳到 [05_基础设施_外部依赖_运行支撑.md](./05_基础设施_外部依赖_运行支撑.md)。

## 7. 明确的现状边界

- 当前正式工程主体在 `frontend/`，不是 `Front/site/`。
- 当前后端形态是 Next.js App Router BFF + server-only 服务层 + Drizzle/Postgres，不是独立后端微服务。
- 当前 AI SDK 层未见 Anthropic/OpenAI 正式依赖；`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 与 Kimi 回退配置已在 `frontend/.env.local.example` 预留，调度代码通过 `model-provider.ts` 做模型分类增强与普通聊天生成。
- `workspace` 相关逻辑仍存在 mock/raw store 与 Postgres 镜像并存的过渡状态，改动时必须查 `frontend/src/lib/workspace/server.ts`、`frontend/src/lib/store/raw-shadow.ts` 与 `frontend/src/lib/db/app-store-*`。
- `AI_Dev_Memo/Project_skeleton/**` 是产品/架构意图来源，不等同于当前实现。
