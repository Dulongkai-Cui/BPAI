# 前端页面、组件与数据链路

> 信息来源范围：`frontend/src/app/**/page.tsx`、`frontend/src/components/**`、相关 `frontend/src/lib/*` 服务入口。更新时间：2026-04-11。
>
> 目标：当你准备新增前端功能、改页面、找组件入口时，先用本页确认“页面在哪、数据从哪来、会打到哪些 API / server service / 表”。

## 1. 前端总体结构

当前前端是 **Next.js App Router**。

- 页面入口位于：`frontend/src/app/**/page.tsx`
- API 位于：`frontend/src/app/api/**/route.ts`
- 组件位于：`frontend/src/components/**`
- 服务层位于：`frontend/src/lib/**`

页面形态分两类：

1. **服务端页面直接取数**
   - 常见模式：`requireCurrentUser()` + `get*Data()` / `list*()`
   - 例如工程看板、工单页、文档详情页。
2. **客户端壳层调用 API**
   - 常见模式：组件中 `fetch("/api/..." )`
   - 例如 BP Ask、部分文档管理交互、表单弹窗。

**页面**

- `frontend/src/components/onlyoffice/onlyoffice-sheet-editor-client.tsx`

**主链路**
```text
/docs/documents/[docId]
-> getAssetById(document/sheet/slide)
-> 判断扩展名
-> OnlyOffice 文档/表格/演示编辑器
   or CAD viewer redirect
   or generic 下载页
-> /api/onlyoffice/callback

```

**判断逻辑要点**
- Office 文件进入 OnlyOffice
- `.dwg/.dxf` 走 CAD 查看

**改动时注意**
- 文档页并不是单纯 document 一种，内部会并行查 `document`、`sheet`、`slide` 三类资产
- 编辑器 key 由 `buildOnlyOfficeAssetKey` 生成

**常改文件清单**

### 3.8 BP Ask 页面

**页面**

- `frontend/src/components/bp-ask/bp-ask-workbench.tsx`
- `frontend/src/components/bp-ask/bp-ask-topbar.tsx`

**主链路**
```text
BpAskShell 初始化
-> GET /api/bp-ask/threads
-> 列出 thread summaries

-> GET /api/bp-ask/threads/[threadId]
-> 取 thread detail + messages

发送消息
-> pendingUserMessage 先在前端上屏
-> assistant 独立 loading 动画
```

**当前产品体验特点**
- 普通聊天与任务型请求共用同一个 BP问问入口

- 处理细节默认折叠为“查看处理细节”，不打扰普通对话
- 历史线程支持删除（归档）

## 5. 页面改动时的检查清单

### 如果你改的是服务端页面

先检查：
- 是否直接调用了 `requireCurrentUser()`
- 是否直接调用 `get*Data` / `list*` / `get*Detail`
- 是否还需要补 route，还是可以直接在 server service 聚合

### 如果你改的是客户端组件

先检查：
- 是否通过 `fetch("/api/..." )` 调接口
- 请求返回结构是否与 route 保持一致
- 乐观更新/本地 state 是否会与服务端返回冲突

### 如果你在文档域改东西

额外检查：
- 是否同时影响 browser-state
- 是否影响 file placement / trash / OnlyOffice callback
- 是否影响合作空间共享状态

### 如果你在工单域改东西

额外检查：
- 是否影响工单 stage/status/priority 枚举
- 是否影响派单、交付资源、缺项计数
- 是否影响与 collaboration space / 文档资产的挂接

### 如果你在 BP Ask 改东西

额外检查：
- 是否影响 thread summary / message metadata / rolling summary
- 是否影响 memory_facts 与 execution_tasks/results
- 是否需要同步更新 dispatch 规则和前端展示
