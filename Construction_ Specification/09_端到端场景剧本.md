# 端到端场景剧本

> 目标：把高频业务流程按“用户动作 -> 页面/组件 -> API -> service -> DB/外部依赖 -> 验证点”串起来，方便快速理解整个链路。

## 1. 文档上传 -> 在线编辑 -> 回调落盘

### 用户动作
用户在 `/docs/documents` 上传一个 `.docx` 文件，然后打开并编辑。

### 端到端链路
```text
/docs/documents
-> DesktopFileBrowser
-> POST /api/assets/upload
-> content/server.ts:createUploadedAsset
-> .bpai/storage + content_assets/file_placements
-> 打开 /docs/documents/[docId]
-> OnlyOffice editor client
-> ONLYOFFICE 回调 /api/onlyoffice/callback
-> overwriteAssetBinary
-> 资产内容更新
```

### 关键文件
- `frontend/src/components/docs/desktop-file-browser.tsx`
- `frontend/src/app/api/assets/upload/route.ts`
- `frontend/src/lib/content/server.ts`
- `frontend/src/app/docs/documents/[docId]/page.tsx`
- `frontend/src/app/api/onlyoffice/callback/route.ts`

### 关键表/存储
- `content_assets`
- `file_placements`
- `.bpai/storage`

### 最小验证
- 上传成功
- 页面刷新仍可见
- 打开后进入正确编辑器
- 修改后回写成功

## 2. 新建工单 -> 派单 -> 上传阶段资料

### 用户动作
在 `/work-orders` 新建工单，在详情页派单，并上传阶段资料。

### 端到端链路
```text
/work-orders
-> CreateWorkOrderButton / WorkOrderFormDialog
-> POST /api/work-orders
-> work-order/server.ts:createWorkOrder
-> work_orders + source_intakes + missing_items
-> 进入 /work-orders/[workOrderId]
-> DispatchAssignmentButton
-> POST /api/work-orders/[id]/dispatch-executions
-> assignWorkOrderDispatch
-> dispatch_executions + engineering_*
-> WorkOrderStageAssetPanel
-> POST /api/work-orders/[id]/stage-assets
-> ensureWorkOrderStageFolders + createUploadedAsset
-> content_assets/file_placements + work_order_document_links
```

### 关键文件
- `frontend/src/app/work-orders/page.tsx`
- `frontend/src/components/work-order/create-work-order-button.tsx`
- `frontend/src/app/api/work-orders/route.ts`
- `frontend/src/app/work-orders/[workOrderId]/page.tsx`
- `frontend/src/components/work-order/dispatch-assignment-button.tsx`
- `frontend/src/components/work-order/work-order-stage-asset-panel.tsx`
- `frontend/src/lib/work-order/server.ts`

### 关键表
- `work_orders`
- `source_intakes`
- `dispatch_executions`
- `missing_items`
- `work_order_document_links`
- `engineering_members`
- `engineering_squads`
- `content_assets`
- `file_placements`

### 最小验证
- 工单创建成功并出现在列表
- 派单后详情页和工程看板同步变化
- 阶段资料上传后，文件出现在对应阶段文件夹并挂接到工单

## 3. 创建 BP Ask 线程 -> 发消息 -> 生成摘要/记忆/任务结果

### 用户动作
用户打开 `/bp-ask`，新建线程并发送一条请求。

### 端到端链路
```text
/bp-ask
-> BpAskShell
-> POST /api/bp-ask/threads
-> createConversationThreadForUser
-> conversation_threads
-> POST /api/bp-ask/threads/[threadId]/messages
-> appendMessageToThreadForUser
-> dispatchBpAskPrompt
-> 写 execution_tasks / execution_results
-> 写 assistant message
-> replaceRollingSummary
-> upsertMemoryFact
```

### 关键文件
- `frontend/src/app/bp-ask/page.tsx`
- `frontend/src/components/bp-ask/bp-ask-shell.tsx`
- `frontend/src/app/api/bp-ask/threads/route.ts`
- `frontend/src/app/api/bp-ask/threads/[threadId]/messages/route.ts`
- `frontend/src/lib/bp-ask/server.ts`
- `frontend/src/lib/bp-ask/dispatch.ts`

### 关键表
- `conversation_threads`
- `conversation_messages`
- `conversation_summaries`
- `memory_facts`
- `execution_tasks`
- `execution_results`

### 最小验证
- 线程创建成功
- 消息发送成功
- 刷新后消息仍存在
- DB 中存在 rolling summary / memory fact / execution task/result

## 4. BP Ask 普通聊天 -> Kimi 生成 -> 摘要与记忆

### 用户动作
用户打开 `/bp-ask`，先问候或做轻量元对话，例如“你好”“你是谁”。

### 端到端链路
```text
/bp-ask
-> BpAskShell
-> 发送消息
-> dispatch.ts 任务筛网判断：无明确任务信号
-> chat_general / help_meta / answer_directly
-> kimi.ts: generateChatReplyWithKimi
-> 写 assistant message
-> 写 rolling summary / memory facts / execution task/result
```

### 关键文件
- `frontend/src/lib/bp-ask/dispatch.ts`
- `frontend/src/lib/bp-ask/kimi.ts`
- `frontend/src/lib/bp-ask/server.ts`
- `frontend/src/components/bp-ask/bp-ask-workbench.tsx`

### 最小验证
- 问“你好”“你是谁”
- 确认默认不展开任务细节
- 确认回复风格符合 BPAI / BP问问身份

## 5. BP Ask 历史删除与即时发送

### 用户动作
用户删除历史线程，或发送一条消息。

### 端到端链路
```text
删除历史线程
-> BpAskSidebar 删除按钮
-> DELETE /api/bp-ask/threads/[threadId]
-> archiveConversationThreadForUser
-> conversation_threads.status = archived
-> 线程列表只保留 active

发送消息
-> BpAskShell.handleSubmit
-> pendingUserMessage 先在前端上屏
-> assistant loading 动画单独显示
-> POST /api/bp-ask/threads/[threadId]/messages
-> 返回正式 thread 后替换临时态
```

### 关键文件
- `frontend/src/components/bp-ask/bp-ask-sidebar.tsx`
- `frontend/src/components/bp-ask/bp-ask-shell.tsx`
- `frontend/src/components/bp-ask/bp-ask-workbench.tsx`
- `frontend/src/app/api/bp-ask/threads/[threadId]/route.ts`
- `frontend/src/lib/bp-ask/server.ts`

### 最小验证
- 删除历史线程后列表即时更新
- 发送消息时，用户消息先显示，assistant 单独 loading

## 6. 工程队看板 -> 创建编队 -> 从工单承接任务

### 用户动作
用户进入 `/engineering/board`，创建编队，并从工单详情页派单到编队。

### 端到端链路
```text
/engineering/board
-> getEngineeringBoardData(user.id)
-> listEngineeringMembers + listEngineeringSquads + getWorkOrderDashboardData
-> CreateSquadButton
-> POST /api/engineering/squads
-> createEngineeringSquad
-> engineering_squads + engineering_squad_members
-> 返回工单详情页
-> 派单到该编队
-> dispatch_executions.assigned_squad_id
```

### 关键文件
- `frontend/src/app/engineering/board/page.tsx`
- `frontend/src/components/engineering/create-squad-button.tsx`
- `frontend/src/app/api/engineering/squads/route.ts`
- `frontend/src/lib/engineering/server.ts`
- `frontend/src/lib/engineering-team/server.ts`

### 关键表
- `engineering_members`
- `engineering_squads`
- `engineering_squad_members`
- `dispatch_executions`

### 最小验证
- 编队创建成功
- 看板中显示新编队
- 派单后编队与成员状态变化可见

## 7. 登录 -> 恢复会话 -> 登出

### 用户动作
用户登录、刷新页面、登出。

### 端到端链路
```text
/login
-> LoginForm
-> POST /api/auth/login
-> authenticateUser
-> 写 sessions + cookie
-> 刷新后 /api/auth/session 恢复登录态
-> POST /api/auth/logout
-> 清理 session
```

### 关键文件
- `frontend/src/components/auth/login-form.tsx`
- `frontend/src/app/api/auth/login/route.ts`
- `frontend/src/app/api/auth/session/route.ts`
- `frontend/src/app/api/auth/logout/route.ts`
- `frontend/src/lib/auth/server.ts`

### 关键表/状态
- `users`
- `sessions`
- `bpai_session` cookie

### 最小验证
- 正确密码登录成功
- 错误密码登录失败
- 刷新后仍保持登录
- 登出后 session 失效
