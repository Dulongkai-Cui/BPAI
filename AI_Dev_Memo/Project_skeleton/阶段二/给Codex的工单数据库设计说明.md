## 工单是什么感觉

工单是电信工程业务的**主线**。一个工程从客户提需求开始，到最后图纸交付、资源录入、稽核完成，整个生命周期都挂在一个工单上。

不是简单的"任务单"，而是**会跨阶段、会卡壳、会补材料、会转来转去**的真实业务对象。

---

## 核心流程（9个环节）

```
来源（邮箱/微信/电话） → 工单登记 → 派单 → 预警（如有） → 现场施工 → 回单 → 竣工图纸交付 → 录资源 → 资源稽核 → 打包图纸出设计
```

关键点：
- **允许先开工、后补材料** —— 现场情况复杂，不能卡死在"材料不齐就不能创建工单"
- **阶段之间会来回跳** —— 稽核不通过要退回补材料，预警可能触发重新派单
- **每个环节都有原始证据** —— 微信截图、现场照片、签字扫描件、CAD图纸，这些都要挂接

---

## 角色分工

| 角色 | 典型操作 |
|------|---------|
| 客服/调度 | 登记工单、派单、盯进度 |
| 工程队主管（如刘主管） | 看自己名下的工单列表、补录进展、上传现场材料 |
| 执行人 | 接单、施工、回单 |
| 稽核人员 | 资源稽核、打回或放行 |
| AI助手 | 从邮件/微信抽摘要、识别缺失项、建议补录路径 |

## 数据结构的核心判断

我们定的方案是：**一个主表 + 四张附表 + 缺失项机制**

不是一张超级大表，也不是每个环节各一张孤立小表。

### 主表（WorkOrder）—— 管全局状态
- 工单编号、标题、业务类型、当前阶段、当前状态
- 当前责任人/责任团队、优先级、是否预警
- 材料完整度、缺失项数量、阻塞项数量
- 计划/实际时间、下一步动作、最新进展摘要

主表是**唯一真源**，所有人先到这里看"这单现在到底在哪"。

### 四张附表——管阶段详情

1. **来源与需求附表（SourceIntake）**
   - 来源渠道、原始内容、客户原话、AI抽取结果
   - 保留原始证据（邮件截图、微信记录）

2. **派单与执行附表（DispatchExecution）**
   - 派单轮次、承接人、计划/实际开工完工时间
   - 施工状态、异常记录、预警原因、协调记录

3. **交付与资源附表（DeliveryResource）**
   - 回单状态、竣工图纸交付清单
   - 录资源状态、资源稽核结论、打包出设计状态

4. **缺失项与补录附表（MissingItem）**
   - 这是"先干活后补材料"能成立的关键
   - 缺什么、缺在哪个阶段、是否阻塞、谁来补、什么时候补

### 合作空间中的"系统表单工作台"

工程队主管（如刘主管）不会天天去翻完整详情页，他需要一张**底表**：
- 分配到我名下的单子有哪些
- 当前阶段、卡在哪里、缺什么材料
- 能快速补录进展、上传现场照片

这张工作台是**主表+附表的投影视图**，不是新的真源。

---

## 缺失项机制（重点）

真实业务允许"不完整启动"，但系统要显式化管理：

1. **创建门槛低** —— 标题、来源类型、大致项目、责任人，就能建单
2. **阶段门槛明确** —— 不是卡"创建"，而是卡"能否进入下一阶段"
3. **缺失项显式化** —— 缺什么不要藏在备注里，要形成正式记录
4. **区分阻塞/非阻塞** —— 有些缺了可以继续干，有些必须补齐才能下一步
