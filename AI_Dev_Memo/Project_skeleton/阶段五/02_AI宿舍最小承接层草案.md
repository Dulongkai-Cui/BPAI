# AI宿舍最小承接层草案

## 1. 核心判断

AI宿舍第一版不应该直接做成完整 AI 员工平台。

阶段五的合理目标是：

> **先把 AI宿舍做成 execution task 的最小承接层。**

也就是说，先让它能看见 BP问问派来的任务、理解任务状态、生成最小执行反馈，再逐步接入工具链和 Longxia。

---

## 2. 最小承接层应包含什么

### 2.1 execution task 看板

AI宿舍第一版应能展示：

- 任务 ID
- 发起用户
- threadId
- sourceMessageId
- executorKind
- primaryIntent
- targetDomain
- executionMode
- status
- confidence
- needsTools
- requiresWrite
- requiresConfirmation
- targetRefs
- constraints
- createdAt / updatedAt

来源表：

- `execution_tasks`

### 2.2 execution result 面板

应能展示：

- taskId
- status
- summaryText
- responseText
- structuredPayload

来源表：

- `execution_results`

### 2.3 最小执行器类型

第一版不需要接全量执行器，但至少要有类型概念：

- `bp_ask`：BP问问自己处理
- `kimi`：模型辅助处理
- `system`：系统受控写入或工具动作
- `longxia`：未来龙虾执行器

这些已经在 `execution_executor_kind` 中出现。

---

## 3. 最小状态流转

可以先沿用当前状态：

- `pending`
- `planned`
- `delegated`
- `completed`
- `failed`
- `cancelled`

阶段五建议先把它们解释清楚：

| 状态 | 含义 |
| --- | --- |
| `planned` | BP问问已经生成调度计划，但尚未由后场执行 |
| `delegated` | 已委托给外部执行器或未来 Longxia |
| `completed` | 后场已完成执行并写入结果 |
| `failed` | 后场执行失败 |
| `cancelled` | 用户或系统取消任务 |
| `pending` | 任务进入队列但尚未规划 |

---

## 4. 第一版模拟承接器

在真实工具链未接入前，AI宿舍可以先做模拟承接器。

### 4.1 对只读任务

当：
- `executionMode = retrieve_then_answer`
- `executionMode = retrieve_and_summarize`

模拟承接器可以返回：
- 将读取哪些对象
- 将用哪些 toolHints
- 当前缺哪些真实工具
- 后续需要接入哪个 service

### 4.2 对写入任务

当：
- `requiresWrite = true`

模拟承接器应该返回：
- 写入预案
- 需要确认的字段
- 需要校验的权限
- 不直接执行真实写入

### 4.3 对 Longxia 任务

当：
- `executorKind = longxia`
- 或 `executionMode = delegate_to_longxia`

模拟承接器应该返回：
- Longxia 任务草案
- 输入 payload 草案
- 等待 LongxiaAdapter 接入

---

## 5. 第一版页面建议

AI宿舍第一版可以从一个最小页面开始：

```text
/ai-dorm/tasks
```

或先挂在工程/系统后台下作为实验页。

页面只需要：

- 任务列表
- 任务详情
- 当前 execution result
- 按 executorKind / targetDomain / status 筛选
- 显示 structuredPayload

暂不需要：

- AI员工管理
- 复杂技能商店
- 多执行器图谱
- 计费/权限复杂面板

---

## 6. 与 BP问问的关系

BP问问负责：

- 接用户输入
- 判断任务
- 生成 execution task
- 给用户解释当前状态

AI宿舍负责：

- 接 execution task
- 管理执行器状态
- 写 execution result
- 未来接 Longxia / tools / workflow runner

---

## 7. 一句话总结

AI宿舍最小承接层第一版只要做到：

> **让 BP问问派出的 execution task 有一个可见、可追踪、可扩展的后场。**
