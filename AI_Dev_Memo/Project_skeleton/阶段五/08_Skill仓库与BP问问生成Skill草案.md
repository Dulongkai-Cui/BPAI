# Skill仓库与 BP问问生成 Skill 草案

## 1. 为什么 Skill 仓库要成为 AI宿舍一级板块

如果 AI宿舍只做：
- Workflow
- AI员工

那“单点能力”会无处沉淀。

BP问问当前已经具备：
- 对话入口
- 任务筛网
- Kimi 普通聊天
- execution task/result

因此阶段五很自然要往前走一步：

> **让 BP问问不仅能理解任务，还能帮用户产出 Skill 草案。**

这就要求 Skill 仓库成为独立板块，而不是附属在 Workflow 下面。

---

## 2. Skill 仓库的核心定位

Skill 仓库负责：

- 管理系统内可复用的单点能力
- 承接外部上传 skill
- 提供模板化 skill 创建入口
- 提供 BP问问生成 skill 的入口

一句话理解：

> Skill 仓库负责“把一个能力沉淀成可复用资产”。

---

## 3. Skill 仓库里应该有哪几种入口

### 3.1 上传现成 skill

适合：
- 别人已经写好的 skill
- 团队共享 skill
- 外部导入 skill

### 3.2 按模板创建 skill

适合：
- 读取型 skill
- 分析型 skill
- 草稿生成型 skill
- 写入预案型 skill

### 3.3 BP问问生成 skill

这是阶段五最有产品感的一步。

用户可以在 Skill 仓库里通过一个小型 BP问问窗口说：

- “帮我生成一个读取工单详情并返回摘要的 skill”
- “帮我做一个检查合作空间待确认意见的 skill”
- “帮我做一个识别最新上传 CAD 元信息的 skill”

然后 BP问问给出：
- skill 草案
- 输入输出定义建议
- 描述与适用场景

---

## 4. Skill 仓库中的 BP问问小窗口

这里的小 BP问问不是新的独立入口，而是：

> **Skill 仓库内部的生成辅助器。**

它的职责应限定为：
- 把自然语言需求转成 skill 草案
- 辅助用户选模板
- 辅助补全输入输出
- 辅助起名与写说明

而不是：
- 直接替代 Skill 仓库页面本身
- 直接变成长期存放一切能力的地方

---

## 5. Skill 与 Workflow 的关系

### Skill
- 单点能力
- 原子工具
- 可复用组件

### Workflow
- 多步流程
- 串联多个 skill / AI员工 / 条件节点
- 更像流程图或流水线

所以：
- Skill 仓库负责“能力资产”
- 工作流工坊负责“能力编排”

---

## 6. 与当前已完成成果的衔接

当前 BP问问已经能：
- 理解任务
- 做普通聊天生成
- 输出 execution task/result
- 模拟执行

因此 BP问问生成 Skill 的合理路径应是：

```text
用户在 Skill 仓库里通过 BP问问描述能力
-> BP问问理解需求
-> 生成 skill 草案
-> 写入 Skill 仓库草稿态（未来）
-> 用户再确认 / 编辑
```

阶段五当前不需要立刻做真实写入，只需把这条产品关系说明清楚。

---

## 7. 一句话总结

Skill 仓库成为 AI宿舍一级板块的意义是：

> **让 BP问问不只是会接任务，还能帮用户把能力沉淀成可复用的 skill 资产。**
