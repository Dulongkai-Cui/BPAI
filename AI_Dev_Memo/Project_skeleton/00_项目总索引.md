# Project_skeleton｜BPAI 项目骨架总索引

## 1. 这套文档是干什么的

`Project_skeleton` 用来沉淀 BPAI 的整体项目骨架、产品结构、模块职责、功能要求、测试点与验收标准。

它不是单页说明，也不是临时备忘录，而是后续整体产品 PRD 的第一版主干。

当前文档建立在以下事实之上：

- `Front/site/` 已经形成六大模块静态原型骨架
- `frontend/` 已经从最小化 Next.js 脚手架演进到阶段一可运行前端基座，文档空间、合作空间、回收站、总览地图和本地 BFF 已接通
- BPAI 后续将围绕“BP问问做调度、AI宿舍做执行、文档档案室承接协作与资产、工单承接落地流转”来展开整体产品设计

---

## 2. 当前项目认知基线

### 2.1 当前顶层模块

当前项目已经形成 6 个顶层模块：

1. BP问问
2. 总览
3. 工程队
4. 工单
5. 文档档案室
6. AI宿舍

对应现有原型入口：

- BP问问 → `Front/site/bp-ask.html`
- 总览 → `Front/site/dashboard.html`
- 工程队 → `Front/site/engineering-hub.html`
- 工单 → `Front/site/work-orders.html`
- 文档档案室 → `Front/site/docs-home.html`
- AI宿舍 → `Front/site/ai-home.html`

### 2.2 当前技术现状

- `Front/site/`：当前最完整的产品原型与信息架构来源
- `frontend/`：当前正式前端工程目录，已形成阶段一可运行基座
- 当前前端已经具备：登录会话、本地 JSON BFF、我的文档空间、合作空间、回收站、OnlyOffice 文档/表格/演示编辑链路、合作空间系统表单控制入口
- 总览模块当前已切到开源地图底图路线，以长沙为固定视角做第一版占位和后续点位承接
- 后续正式前端落地应以本套文档为产品主线，而不是直接把静态页平移

### 2.3 当前 AI 主干认知

BPAI 第一阶段推荐采用如下主干：

用户提需求
→ BP问问做识别、拆解、调度
→ 选择自答 / 工具 / 工作流 / 龙虾(Open Claw)
→ 执行层返回结果
→ BP问问整合结果并向用户输出

其中：

- BP问问负责“想清楚、叫对人、收结果、说人话”
- AI宿舍里的 Open Claw / AI员工 / 工作流负责“真干活”

### 2.4 当前文档协作认知

文档档案室第一阶段推荐采用：

- 单编辑者锁
- 多人旁观评论
- 权限解锁编辑

这套机制尤其适合工程管理、表格台账、流程型文档、送审材料、验收文档，以及未来接入 OpenClaw skill 的场景。

## 5. 本套文档覆盖什么

本套文档重点覆盖：

- 产品定位
- 模块职责与边界
- 信息架构与模块地图
- 角色与核心使用场景
- AI 编排链路
- 文档协作机制
- 前端原型与正式工程衔接关系
- 各模块功能要求
- 各模块测试点与验收标准

---

## 6. 本套文档当前不覆盖什么

当前版本暂不深入到以下层级：

- 具体接口字段定义
- 具体数据库表结构
- 具体前端组件实现代码
- 具体后端微服务拆分
- 最终视觉稿规范
- 全量业务规则明细

这些内容会在后续技术设计、接口设计、研发拆解阶段继续展开。
